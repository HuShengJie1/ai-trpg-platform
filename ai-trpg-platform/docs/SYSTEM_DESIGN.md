# System Design / 系统总体设计

## 项目定位

AI TRPG Platform 是一个 AI 辅助跑团平台。系统目标是把模组资料、角色车卡、投骰、战役聊天、规则查询和玩家社区整合在同一个应用中，并在后续通过 RAG 与大模型能力支持 AI 主持人带团。

本阶段只定义系统边界、模块职责和核心流程，不实现完整业务逻辑。

## 模块设计

### 1. 用户模块

用户模块负责账号注册、登录、身份识别和用户资料。后续会支持 JWT 鉴权、用户角色、权限控制，以及用户与角色卡、战役、论坛内容之间的归属关系。

### 2. 角色车卡模块

角色车卡模块负责保存玩家角色资料，包括基础信息、属性、技能、物品、状态和备注。不同规则系统的车卡结构可能不同，因此后续可以用 JSON 字段保存规则相关扩展数据。

### 3. 投骰模块

投骰模块负责解析投骰表达式、生成投骰结果并保存历史记录。后续将支持常见表达式，例如 `1d20+5`、`3d6`、优势/劣势，以及与战役消息关联的判定记录。

### 4. 模组管理模块

模组管理模块负责创建和维护跑团模组的元数据，例如标题、简介、作者、规则系统、可见性和所属用户。模组可以关联一个或多个上传文件，并生成可检索的文本块。

### 5. PDF 模组导入模块

PDF 模组导入模块负责接收用户上传的 PDF 文件，保存文件信息，并在后续使用 PyMuPDF 提取文本。本阶段只预留 `pdf_parser.py` 服务，不实现真实解析逻辑。

### 6. 模组知识库 RAG 模块

RAG 模块负责把解析后的 `module_chunk` 转换为可检索知识库。后续会预留 pgvector 向量字段，支持 embedding 生成、相似度检索、关键词检索和混合检索。

### 7. AI 带团模块

AI 带团模块负责根据当前战役状态、角色信息、最近聊天记录和检索到的模组内容构造 AI 主持人 prompt。后续可接入 OpenAI API 或其他大模型 API。本阶段只预留 `ai_service.py`。

### 8. 战役存档模块

战役存档模块负责保存战役元数据、参与角色、聊天消息、AI 回复、玩家行动、投骰记录和战役状态。它是 AI 带团流程的核心上下文来源。

### 9. 规则查询模块

规则查询模块负责保存和检索规则条目，支持按关键词、标签、规则系统查询。后续可增加 AI 规则问答接口，但不会导入或生成版权规则书内容。

### 10. 玩家论坛模块

玩家论坛模块负责社区讨论，包括分类、发帖、回帖、标签和搜索。论坛内容与用户账号关联，后续可以扩展审核、收藏、点赞和通知。

## 核心业务流程

```text
上传 PDF 模组
→ PDF 文本解析
→ 切分 module_chunk
→ 生成模组知识库
→ 创建角色
→ 创建战役
→ 玩家输入行动
→ 检索模组内容
→ AI 主持人回复
→ 投骰判定
→ 保存聊天记录和战役状态
```

## 关键边界

- 上传文件只保存用户提供的内容，不内置版权模组或规则书。
- AI service 只负责调用抽象，不直接绑定单一模型供应商。
- RAG service 负责检索上下文，不负责决定剧情走向。
- 投骰 service 负责随机和表达式解析，不负责角色规则解释。
- 战役模块负责把角色、模组、聊天和投骰串联起来。

## 后续实现原则

- 优先实现纵向最小闭环：角色、模组、战役、聊天、投骰。
- 数据库模型与 API schema 分层维护。
- 复杂规则系统以可扩展 JSON 字段和规则插件化方向预留。
- AI、PDF、RAG 相关能力通过 service 层隔离，便于替换供应商和实现方式。
